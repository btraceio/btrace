## Must decide or fix before RC

1. **`enableAt` / `@Level` gating fails open — FIXED in the working tree later the same day** (two bugs: the
   handler-name lookup below, and `createNoopMH` rejecting `void` so guard construction threw and fell
   back to the unguarded handler; regression test `testOnMethodLevelSuppressesHandlerAboveLevel`).
   Original finding:
   `HandlerRepositoryImpl.applyLevelGuard` (line ~108) matches `om.getMethod()` (the traced-method
   matcher, e.g. `callA`) against `simpleHandlerName` (the probe handler name, used for
   `getDeclaredMethod`). They never match for a normal probe, so no guard is installed and leveled
   probes fire at any level. The bytecode-layer level check was already removed in favour of this
   layer. `testOnMethodLevel` only asserts that probes fire at `level=200` against `@Level("100")` and
   `@Level("150")`, so it passes vacuously. Fix is one-line (`getTargetName()`) plus a suppression
   regression test; alternatively document the feature as non-functional in 3.0.0. Shipping a
   documented gating feature that silently no-ops is in the checklist's own "always NO-GO" family.
2. **Bad `-javaagent` options abort the user's JVM with a raw stack trace — FIXED (738571ca):** an invalid
   `port`/`bindAddress` is now reported as `invalid agent option <name>=<value>` and the agent starts
   without a command server; the JVM and startup scripts keep running. Original finding: `port=70000` and
   `bindAddress=0.0.0.0` throw from `ControlServer.open` during `premain`; the JVM exits 134 and the
   message never names the option or value (QE cases `agent-args.port-out-of-range`,
   `agent-args.bind-address-non-loopback`, committed as S1). Fail-fast may be intended, but the
   message must name the option and the exit should not be a crash dump. Same family: non-numeric
   `fileRollMaxRolls` swallowed, unknown option typos dropped silently, `script=<missing>` silently
   not loaded, `statsd=host:port:extra` silently ignored (all S4 in `btrace-qe/EXPLORATION.md`).
