# BTrace 3.0.0 — Feature Map (v2.2.6 → develop)

Date: 2026-07-11
Scope: all 296 non-merge commits in `v2.2.6..develop` (`git log --no-merges v2.2.6..develop`), 1309 files changed (+105169/−27071).
Baseline for the release: root `build.gradle:12` already sets `version = '3.0.0-SNAPSHOT'`; `settings.gradle` names the root project `btrace-ng`.

Each feature lists: what it does, proof (commits / files), user-visible surface, its Java-version dependency, and how it relates to the planned **Java < 17 deprecation** (3.0.0 emits a warning on JVMs older than 17; support removed in the next major release).

Legend for the deprecation column used throughout:
- **enables removal** — the feature exists (at least partly) to support pre-17 JVMs and can be deleted in 4.0
- **unaffected** — works identically on 8 and 17+
- **17+ leaning** — already effectively requires a modern JDK

## A. Breaking / identity changes

### A1. Package + coordinates rename: `org.openjdk.btrace` → `io.btrace` (BREAKING)
- All sources, SPI files, probe XMLs, manifests and the Maven group ID renamed. Group: `build.gradle:11` (`group = 'io.btrace'`).
- Pre-compiled legacy probes keep working: `ProbePackageMigrator` ASM-remaps `org/openjdk/btrace/` → `io/btrace/` at load time (`btrace-agent/src/main/java/io/btrace/instr/ProbePackageMigrator.java`, commit `66940619`).
- Commits: `7bb65e94`, `95e9a816`, `a773bb32`, `8c2c126b`, `57dabbb8`, `0d7591e4`, `342f44af`, `14defaa9`, `f29dcc33`, `ed98c6de`, `e3a08714`, `aa806c56`, `7f82f5c0`.
- Breaking: script sources importing `org.openjdk.btrace.*` must be updated (or rely on auto-imports, see C1); Maven consumers must switch to `io.btrace:*`.
- Deprecation relation: **unaffected** (the migration shim itself runs on Java 8+).

### A2. Relicensing GPLv2+CE → Apache 2.0
- `LICENSE`, `NOTICE`, `license.header`; header replacement across the tree plus clean-room rewrites of externally attributed lines.
- Commits: `910f0a79`, `4c011312`, `7176e0e5`, `939fc431`, `27bdaac7`, `213c40f7`; rewrites `d95cf70f`, `30a99856`, `b8bc452d`, `3fafccb3`, `13ad2e84`, `62b8ca9b`, `2fc63a31`, `fe817951`.
- Known stale spot: `docker/Dockerfile` OCI label still declares GPL (see gap analysis).
- Deprecation relation: **unaffected**.

### A3. Masked-JAR single-artifact distribution (BREAKING packaging)
- One `btrace.jar` serves as agent, client, and boot artifact. Bootstrap classes ship as `.class`; agent/client/shared classes ship as `.classdata` under `META-INF/btrace/{agent,client,shared}/`, invisible to app classloaders; `io.btrace.boot.Loader` (manifest `Premain-Class`/`Agent-Class`/`Main-Class`) unmasks the right section. Legacy separate-jar/uber-jar packaging removed.
- Files: `btrace-boot/src/main/java/io/btrace/boot/{Loader,MaskedClassLoader,MaskedJarUtils}.java`; packaging in `btrace-dist/build.gradle` (`btraceJar` task, manifest incl. `BTrace-Version`).
- Commits: `de2322bc`, `f59e79a6`, `f62f077e`, `35093bc0`, `a837fe6f`, `bdbda6ff`, `0418c0d5`.
- Deprecation relation: **unaffected**; `Loader.premain`/`agentmain`/`main` (`Loader.java:76/87/97`) is the earliest possible emission point for the < 17 warning.

### A4. Module consolidation
- `btrace-instr` module removed; its code lives in package `io.btrace.instr` inside `btrace-agent`. New `btrace-boot` module. `settings.gradle` auto-includes `btrace-*` dirs + nested `btrace-extensions:*`.
- Commits: `7a2eb349`, `6f602645`, `1a260e76`.
- Breaking: Maven consumers of the old `btrace-instr` artifact.
- Deprecation relation: **unaffected**.

### A5. `libs`/profiles DEPRECATED (BREAKING CHANGE, removal planned "after N+2")
- Replaced by extensions (B) + manifest-libs: classpath additions via JAR-manifest attributes `BTrace-Boot-Libs`, `BTrace-System-Libs`, `BTrace-Libs-Root`, `BTrace-Libs-Profile` (`btrace-agent/src/main/java/io/btrace/agent/AgentManifestLibs.java`), behind feature flag `btrace.feature.manifestLibs`.
- Deprecation warnings already emitted: `btrace-agent/src/main/java/io/btrace/agent/Main.java:739-747, 952-962`.
- Commits: `f8534f38` (BREAKING CHANGE footer), `4fa3793b`, `cd3ef50f`, `807f457a`.
- Deprecation relation: **unaffected** technically, but 3.0.0 release notes must state both deprecations (libs *and* Java < 17) side by side, with removal targets.

## B. Extension ecosystem

### B1. Permission-based extension framework
- Extensions = packaged artifacts (API as bootstrap `.class`, impl as isolated `.classdata`), discovered from: embedded in agent JAR → `$BTRACE_HOME/extensions/` → `~/.btrace/extensions/` → `$BTRACE_EXT_PATH`; injected into scripts via `@Injected` (`btrace-core/src/main/java/io/btrace/core/annotations/Injected.java`); gated by a 3-tier permission model (default / standard / privileged) in `Permission` enum + `PermissionPolicy` (reads `btrace.permissions` prop, `~/.btrace/permissions.properties`, `~/.config/btrace/permissions.properties`, `META-INF/btrace/permissions.properties`).
- Key files: `btrace-core/src/main/java/io/btrace/core/extensions/` (Extension, Permission, @ExtensionDescriptor, @ServiceDescriptor, ExtensionContext), `btrace-core/src/main/java/io/btrace/extension/` (PermissionPolicy, impl/ExtensionBridgeImpl, impl/ExtensionLoaderImpl, impl/ClassDataLoader, impl/EmbeddedExtensionRepository), compile-time checks in `btrace-compiler/src/main/java/io/btrace/compiler/VerifierVisitor.java`.
- Commits: `6df70c78`, `8f80077d`, `87999d44`, `795ad8a9`, `3a3a2904`, `b7cfd46e`, `d7a3e268`, `883e8d7a`, `ad11d5a8`, `f476295e` (removed earlier probe-level permission API), `e74a6e3f`, `4a982a90`.
- User surface: agent args `allowExtensions=`/`denyExtensions=`/`allowPrivileged=`; client CLI `-le` (list failed extensions; `btrace-client/src/main/java/io/btrace/client/Main.java:221`, interactive menu option 7, commit `b5f6be05`); sysprops `btrace.permissions`, `btrace.extensions.config`.
- Deprecation relation: **unaffected** (extension metadata even defaults `java.version` to `"8+"`, `EmbeddedExtensionRepository.java:213`). NOTE: `docs/ExtensionInterfaceRules.md` mandates Java-8-compatible extension APIs (no default/private interface methods, rule BTRACE-EXT-002) — this rule is a candidate to relax in 4.0 once < 17 is removed; in 3.0 it stays.

### B2. Bundled extensions
- `btrace-extensions/btrace-statsd` (statsd moved out of core agent, `@ExtensionDescriptor(permissions={NETWORK})`, commit `9451f1da`), `btrace-utils` (PrinterService), `btrace-metrics` (HdrHistogram latency histograms), `btrace-dtrace` (DTraceExtension, commit `d25952fc`).

### B3. Provided-style extensions + examples

### B4. `btracex` extension-management CLI + TUI (new tool)
- `bin/btracex` (`btrace-dist/src/main/resources/bin/btracex{,.bat}`): `inspect [--json]`, `list [--json]`, `policy print|set|edit`, `install <gav|zip|url>`; lanterna TUI repository browser.

## D. Instrumentation engine

### D1. INVOKEDYNAMIC handler isolation, detach-safe dispatch (#830)
- Probe-handler calls dispatch through `MutableCallSite`s; detach resets targets to no-ops (no retransform), reattach relinks; BTrace code is blocked while the JVM links an indy (`LinkerInstrumentor` instruments `java.lang.invoke.MethodHandleNatives`; `LinkingFlag` bootstrap-only).
- Files: `btrace-runtime/src/main/java/io/btrace/runtime/IndyDispatcher.java`, `btrace-agent/src/main/java/io/btrace/instr/LinkerInstrumentor.java`, agent `Main.java:250-261`.
- Commits: `a40689fe` (#830); groundwork `ae8b2413`, `fb2ab2bd`, `6d94e1dc`, `644ebe0a`.
- Java dependency: **explicitly replaces the old JDK 15-only `Indy` path with a Java 8+ dispatcher**; `btrace-runtime` no longer has a `java15` sourceSet (only `java9`, `java11`).
- Deprecation relation: **unaffected** — this work *increased* pre-17 compatibility; worth an explicit note in release notes that 3.0 still fully supports 8–16 while deprecating them.

### D2. InstrumentationBackend SPI + ClassFile API backend (class-file version > 69)
- Pluggable backends: ASM handles class-file major ≤ 69 (Java 25; `AsmInstrumentationBackend.java:29` `MAX_ASM_MAJOR_VERSION = 69`); newer classes go to a `java.lang.classfile`-based backend (`btrace-agent/src/main/java24/io/btrace/instr/ClassFileApiBackend.java`), loaded reflectively by `BackendSelector.java` (logs "ClassFile API backend unavailable (expected on JDK < 24)" when absent).
- Limitation: ClassFile backend currently covers only `Kind.ENTRY`/`Kind.RETURN` probes.
- Build: `btrace-agent/build.gradle` `java24` sourceSet compiled with a JDK 24 toolchain, merged into the jar root — NOT a formal Multi-Release JAR (no `Multi-Release: true` manifest anywhere); safe only because the class is loaded reflectively.
- Commits: `93090c67`, `d636f193`, `2393e77a`, `8ec3109c`, `83dbda68`, `95acb672`, `e47de241`.
- Java dependency: **needs JDK 24+ at runtime to engage**; engaged only for class-file versions ≥ 70 (Java 26+ targets).
- Deprecation relation: **17+ leaning** — the flagship "future JDKs" feature; a good headline argument for why the project's center of gravity moves to modern JDKs.

### D3. Performance & correctness improvements (instr)
- Handler bytecode caching (`1e444a23`), compiled class-pattern cache (`b5656665`), CallGraph O(1) index (`bb6f432b`), VariableMapper allocation reduction (`80e88612`), action-prefix cache (`89c77cfc`), MethodTracker origMeans fix (`07b1d6ca`), stackmap-frame fixes + hardened frame locals + configurable codegen (`116f8982`, `42c40864`, `2cc2a1f9`, `d7c0eda7`, `4d2b3964`), `InstrumentationException` instead of magic values (`4e543d89`), array remapping fix (`60eea540`), range/level check fix (`9e9b9a26`).
- New debug/validation sysprops: `btrace.verify.transformed`, `btrace.verify.filter` (`BTraceTransformer.java:195,198`), `btrace.verifier.dump` (`BTraceProbePersisted.java:530`), `btrace.validation.warn`/`btrace.validation.info` (`MethodInstrumentor.java:484-486`).
- Deprecation relation: **unaffected**.

### D4. JDK 25 compatibility
- Thread accessor exclusions (`ClassFilter.java` ~L86-108: `threadLocals`/`inheritableThreadLocals`/`terminatingThreadLocals`, `setThreadLocals`; commits `555d1e64`, `6929db2f`), `InaccessibleObjectException` handling in runtime impls (`e79d2da6`; `BTraceRuntimeImpl_9.java:94,106`, `BTraceRuntimeImpl_11.java:116,128`), agent stabilization (`2ec742f9`), Thread instrumentation functional test (`6291a2c6`), scheduled JDK-version-update CI (`7dd7a83d`, `scripts/update-jdk-versions.sh`).
- Deprecation relation: **17+ leaning** — demonstrates the maintenance cost is on the *new*-JDK side; pre-17 tiers are pure legacy carry.

## F. Java-version support map (ground truth for the deprecation)

### F1. Effective support tiers in code (none of them is 17)
| Tier | Mechanism | Proof |
|---|---|---|
| Java 8 | `BTraceRuntimeImpl_8` selected when `java.lang.Module` is absent; `sun.misc.Perf`/`Unsafe` | `btrace-runtime/src/main/java/io/btrace/runtime/BTraceRuntimeImpl_8.java:58-64, 30-31` |
| Java 9–10 | `BTraceRuntimeImpl_9` (`major == 9 || major == 10`); `jdk.internal.perf` | `btrace-runtime/src/main/java9/.../BTraceRuntimeImpl_9.java:70-74` |
| Java 11+ | `BTraceRuntimeImpl_11` (`feature() >= 11`) | `src/main/java11/.../BTraceRuntimeImpl_11.java:71-74` |
| Java 15+ | `defineHiddenClass` path vs 11–14 `privateLookupIn().defineClass` fallback | `BTraceRuntimeImpl_11.java:215-251` |
| Java 24+ | ClassFile API backend (reflective) | `btrace-agent/src/main/java/io/btrace/instr/BackendSelector.java` |

Selection: `BTraceRuntimes.java` static init tries `_11` → `_9` → `_8`, catching `ClassNotFoundException | UnsupportedClassVersionError`. **`BTraceRuntimes.loadFactory` is the single choke point that knows which tier was selected** — the natural place to key the deprecation warning, alongside the once-only guard in agent `Main.main` (`Main.java:168`, `if (Main.inst != null) return;`).

### F2. What exists specifically for < 17 (removal inventory for 4.0)
- `BTraceRuntimeImpl_8` + `BTraceRuntimeImpl_9` classes and the `java9` sourceSet plumbing (`btrace-runtime/build.gradle`).
- JDK 11–14 `defineClass` fallback (`BTraceRuntimeImpl_11.java:215-251`) — removable only if the floor becomes 17 (17 > 15, so the hidden-class path is then unconditional).
- `tools.jar` plumbing: `common.gradle getToolsJar()` (JDK 8 toolchain tools.jar) wired as compileOnly/runtimeOnly in agent/compiler/client builds.
- JDK 8 `AgentLoadException("0")` attach retry: `btrace-client/src/main/java/io/btrace/client/Client.java:749-770` (keys off `java.version` startsWith `"1.8"`).
- Java-8 idioms kept deliberately: `Collections.emptyList()` instead of `List.of()` (commit `a62169b1`; e.g. `AgentManifestLibs.java:68,75`); `sun.misc.Unsafe` import in `btrace-core/.../BTraceRuntime.java:53`; `sun.misc.Signal` in `client/Main.java:40`.
- Extension API Java-8 interface rules (`docs/ExtensionInterfaceRules.md:16,41`, rule BTRACE-EXT-002).
- Build: `common.gradle` `sourceCompatibility = 8` / `targetCompatibility = 8` default; agent compiled on a JDK 8 toolchain (`btrace-agent/build.gradle`); `--add-opens` test conditionals keyed off `"1.8"`.
- CI: test matrix `[8.0.492-tem, 11.0.31-tem, 17.0.19-tem, 21.0.11-tem, 25.0.3-tem, 27.ea.20-open]` (`.github/workflows/continuous.yml:93`); release integration tests `[8, 11, 17, 21]` (`.github/workflows/release.yml:236`).

### F3. Version detection constraint for the warning
The warning code must run on Java 8, where `Runtime.version()` does not exist. Detect via `java.specification.version` (values `1.8`, `9`, `10`, … — parse "1.x" as x) or via the existing tier selection (`BTraceRuntimeImpl_8`/`_9` chosen, or `_11` with `feature() < 17`). Client-side, the *target* VM's version is already available as `serverVmProps.getProperty("java.version")` (`Client.java:749`).

### F4. Warning emission candidates (design decision in the release plan)
1. `io.btrace.boot.Loader.premain/agentmain/main` (`btrace-boot/.../Loader.java:76,87,97`) — earliest, covers every mode, bootstrap-visible.
2. `io.btrace.agent.Main.main(String, Instrumentation)` (`Main.java:168`) — has the idempotence guard; recommended primary site for the target-JVM warning.
3. `BTraceRuntimes.loadFactory` — fires exactly when a pre-17 tier is chosen.
4. `io.btrace.client.Client.attach(...)` (`Client.java:576,632`) — warn about the *target* VM from the client console.
5. `io.btrace.client.Main.main` (`Main.java:108`) — warn about the client's own JVM.
