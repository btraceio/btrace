# BTrace 3.0.0 Release Plan — version bump, Java < 17 deprecation, docs completion

Date: 2026-07-11
Inputs: `2026-07-11-v3.0.0-feature-map.md`, `2026-07-11-v3.0.0-docs-gap-analysis.md`.
Goal: a bullet-proof 3.0.0 that (a) ships everything accumulated since 2.2.6, (b) deprecates running on Java < 17 with a clear once-only warning, (c) has every new feature documented, and (d) leaves users with an unambiguous migration story.

Release policy statement (canonical, use verbatim everywhere):
> BTrace 3.0 runs on Java 8–25+. Running BTrace against a JVM older than Java 17 is deprecated: it continues to work throughout 3.x but emits a deprecation warning. Support for Java < 17 will be removed in the next major release (4.0).

Note the honest framing: nothing in 3.0.0 *requires* 17 (the code tiers are 8 / 9–10 / 11+ / 15+ / 24+, see feature map §F1). The deprecation is a forward-looking maintenance decision, justified by the removal inventory in feature map §F2 and by where new investment lands (ClassFile API backend, JDK 25/26 compatibility).

## Phase 1 — Implement the Java < 17 deprecation warning (code)
1. **Shared helper** in `btrace-core` (compiled at source 8): parse `java.specification.version` ("1.8" → 8, else integer prefix); expose `int javaFeatureVersion()` and `boolean isDeprecatedJavaVersion()` (< 17). Guard with a `static AtomicBoolean warned` for once-only semantics per JVM.
2. **Agent-side warning (primary)**: in `io.btrace.agent.Main.main(String, Instrumentation)` right after the `Main.inst != null` idempotence guard (`btrace-agent/src/main/java/io/btrace/agent/Main.java:168-175`) — fires exactly once per target JVM regardless of premain/agentmain/fat-agent path. Emit to stderr AND the client message channel if a client is connected. Suggested text:
   > `[BTrace] WARNING: This JVM is Java <N>. Running BTrace on Java versions older than 17 is deprecated and will be UNSUPPORTED in the next major BTrace release. Please plan an upgrade to Java 17+. (Suppress with -Dbtrace.suppressJavaDeprecationWarning=true)`
3. **Client-side warning**: in `io.btrace.client.Client.attach(...)` (`btrace-client/src/main/java/io/btrace/client/Client.java:576/632`), reuse the already-read `serverVmProps.getProperty("java.version")` (`Client.java:749`) to warn about the *target* VM on the operator's console (visible even when agent stderr isn't).
4. **Do not** couple the warning to `BTraceRuntimes.loadFactory` tier selection — tiers are 11+/9/8, so an 11-tier JVM at Java 16 would be missed if keyed on the 8/9 factories; use the feature-version helper instead.
5. Tests:
   - Unit: version parsing ("1.8", "9", "11", "16", "17", "21", "25"); once-only behavior; suppression property.
   - Integration: reuse the existing SDKMAN JDK matrix — assert warning present on 8 and 11 lanes, absent on 17/21/25 lanes (extend `integration-tests`, mind the `btrace.port` isolation rules).
6. Docs hooks (Phase 3 consumes): the exact final warning text and the suppression property.

## Phase 4 — Verification (bullet-proofing)
1. **Full matrix run**: `./gradlew :btrace-dist:build` + `:integration-tests:test -Pintegration` across the SDKMAN matrix (8, 11, 17, 21, 25, 27-ea) — all green, with the new warning assertions from Phase 1.5.
2. **Deprecation UX check** on real JVMs: attach via `btrace`, `-javaagent`, fat-agent jar, Docker sidecar, and MCP `deploy_oneliner` to a Java 8 and a Java 11 target → exactly one warning per JVM, correct text; Java 17/21/25 targets → silent.
3. **Migration dry-run**: take a 2.2.6-era compiled probe (org.openjdk.btrace) and a 2.2.6 source script → verify shim migration and source failure modes match the migration guide's instructions.
4. **Protocol compatibility**: 2.2.6 client ↔ 3.0.0 agent and vice versa → V1 fallback works (negotiation).
5. **Docs link check**: run a markdown link checker over `README.md`, `docs/**`, `docker/README.md`, plugin READMEs (catches §3.11–15 regressions); grep-gates in CI or the release checklist: no `org.openjdk.btrace` outside migration-guide/shim contexts, no `GPL` outside NOTICE history, no `2\.[23]\.[0-9]` version strings in docs, no `/Users/` paths.
6. **Doc-vs-code property audit**: grep all documented sysprops (`btrace.comm.*`, `btrace.feature.manifestLibs`, `btrace.permissions`, `btrace.suppressJavaDeprecationWarning`, `btrace.verify.*`, `btrace.validation.*`, `btrace.oneliner.dump`) against `System.getProperty` call sites.
7. **RC flow**: cut `v3.0.0_RC` via `.github/workflows/release.yml`, verify: Maven Central staging artifacts under `io.btrace:*` with Apache-2.0 POM license, SDKMAN default-version update (#850 fix), jbang catalog bump (external `btraceio/jbang-catalog`), Docker images `3.0.0[-alpine|-distroless]`, `btrace --version` output, GitHub auto release notes.

## Phase 5 — Release-notes skeleton (3.0.0 announcement)
1. Headline: new package `io.btrace`, Apache 2.0, single masked `btrace.jar`, extension framework, flat DSL, oneliners, MCP/AI tooling, protocol V2, ClassFile-API future-proofing.
2. Breaking changes: package/coordinate rename (+ shim guarantee for compiled probes), masked-jar packaging, `btrace-instr` artifact removal, removed probe-level permission API (`f476295e`).
3. Deprecations (with removal targets): **Java < 17 (removed in 4.0)**; `libs`/profiles (removal "after N+2" per `f8534f38`) — present both in one "Deprecations" section.
4. Behavior notes: aggregation math fixes (`8df3f1a4`, `1960ed22`), detach-safe indy dispatch, V2 default protocol with auto-fallback.
5. Link: Migration guide, tutorial, GettingStarted.
