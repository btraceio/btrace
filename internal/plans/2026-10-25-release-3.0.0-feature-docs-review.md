# 3.0.0 new-feature review: completeness, consistency, comprehensibility — 2026-10-25

Scope: every feature claimed in `.github/release-notes/v3.0.0.md`, checked against the user docs
(`README.md`, `docs/**`, `docker/README.md`) and against the code on `develop` at `23e61169`.
Four read-only reviewers, one per slice; blockers re-verified by hand. No files changed.

Verdict: the feature set itself is solid (most claims check out end to end), but four items are
release-blocking because the shipped artifacts or the docs say something that is false.

## Blockers

Status: all four fixed on develop later the same day (license files + verifier; aggregation docs and
notes; `grant=` documented as inert and the agent now warns; Getting Started and tutorial metrics
examples require `allowExtensions=btrace-metrics`).

1. **Shipped LICENSE is GPLv2.** `btrace-dist/src/main/resources/LICENSE` is the GPL v2 + Classpath
   Exception text and `COPYRIGHT` is "Copyright 2008 Sun Microsystems"; both are copied into the root
   of every tgz/zip/sdkman zip/deb/rpm and into `/opt/btrace/` in every Docker image. The POM, OCI
   label, README, migration guide and release notes all say Apache 2.0.
   `scripts/verify-release-artifacts.sh` checks only the POM and the image label, so the gate will
   not catch it. Fix: replace both files with the repo `LICENSE`/`NOTICE`, and extend the artifact
   verifier to check archive contents.
2. **Aggregations API is gone but still documented and in the notes.** `f59e79a6` (2026-02-16)
   removed `io.btrace.core.aggregation.*`; nothing under `src/main` defines `Aggregations`,
   `Average`, `Minimum`, `Maximum`. Yet the notes' "Behavior changes" bullet describes fixes to
   `Average`/`Minimum`/`Maximum`, `docs/QuickReference.md:355-366,632-636` and
   `docs/Troubleshooting.md:521-531` still teach `Aggregations.newAggregation(...)`, and
   `Permission.AGGREGATION` is still listed as a default permission in the tutorial. The real
   change for 2.x users, "the Aggregations API was removed", appears in no Breaking-changes list and
   not in the migration guide. Fix: replace the bullet, add the removal to Breaking changes and to
   `Migration-2.x-to-3.0.md`, delete the examples.
3. **`grant=` / `deny=` / `grantAll=` are inert for probe permissions.** Advertised in the notes
   (`:50-51`), `Migration:92`, `README.md:329-331,353`, `BTraceTutorial.md:136-138,814-821,851-857`,
   `PermissionPolicy.md:16-17`. The only consumer is `agent/Client.java:344-352`, which compares
   against `probe.getRequiredPermissions()`, and nothing on the load path populates that set
   (`Verifier.java` ignores `@RequestPermission`; the compiler collects manifest permissions into a
   field nobody reads). Extension linking consults only `allowExtensions=`, `allowPrivileged=`,
   `denyExtensions=` and the policy file. So the tutorial's
   `-javaagent:btrace.jar=script=MetricsProbe.class,grant=NETWORK,THREADS` does not unblock the
   metrics extension. Fix: either wire `grant=` through, or remove it from docs/notes and the
   agent's own error text (`Client.java:698-700`) and name only the effective knobs.
4. **Getting Started's first extension example cannot work as written.** `GettingStarted.md:236-287`
   and `BTraceTutorial.md:897-901` say the metrics extension needs "no special flags", but
   `MetricsService` declares `THREADS`, which is privileged and blocked by default; the required
   `@Injected` then fails fast. `tutorials/04` has it right (`allowExtensions=btrace-metrics`).
   The new-user path through Getting Started dead-ends on the headline feature.

## Should fix before RC (factual errors a reader will hit)

Packaging and install
- `GettingStarted.md:30,33` use the wrong archive names (`btrace-<version>.tar.gz`); real assets are
  `btrace-v<version>-bin.tar.gz` / `-bin.zip`.
- `README.md:154-155,224` promise a `jbang btrace <PID>` alias that only exists after
  `jbang catalog add` as `btrace@btraceio`.
- Legacy multi-jar layout still shown as current: `GettingStarted.md:738`,
  `docs/architecture/fat-agent-plugin.md:10-11`, `docker/Dockerfile.distroless:21`
  (`-javaagent:/opt/btrace/libs/btrace-agent.jar`).
- `GettingStarted.md:847-848` says `io.btrace:btrace` ships without embedded extensions; the build
  publishes the fat agent with the default extensions (`btrace-dist/build.gradle:976-985`), as
  README and Migration say. No doc explains that the Maven jar differs from `libs/btrace.jar`.
- `docs/JDKCompatibility.md:39-42` build-JDK guidance is wrong (Gradle 9.8 needs 17+; CI uses 21 +
  24) and the page is linked from nowhere.
- Container size claims (~25/15/10 MB in `README.md:213-215`, `docker/README.md`) are implausible
  for full-JDK bases; `docker/README.md:56` names a different distroless base than the Dockerfile.
- `README.md:248` and `provided-style-extensions.md:117` give the libs escape hatch as
  `-Dbtrace.trusted=true`; the agent requires the agent argument `trusted=true` and says the
  property has no effect (`Main.java:1294-1298`).

Instrumentation and runtime
- ASM is now 9.11.1 (`settings.gradle:58`, bumped today), which parses Java 28 class files
  (`Opcodes.V28`). Notes `:28-30`, `InstrumentationBackends.md:28,35`, `JDKCompatibility.md:19`,
  `BTraceTutorial.md:2051` still say 9.10.1 and that Java 28 EA is routed to the ClassFile API
  backend "because ASM cannot parse it". Routing still happens only because
  `AsmInstrumentationBackend.MAX_ASM_MAJOR_VERSION = 71` was not bumped with the dependency, which
  `InstrumentationBackends.md:35` promises always happens. Decide: bump the constant to 72 and
  renumber the docs (backend then first engages on JDK 29 EA), or keep 71 and fix the rationale.
- Notes `:30` "all probe kinds are supported" vs documented ClassFile-API limitation (`@Duration`
  on `SYNC_ENTRY`/`SYNC_EXIT`, `InstrumentationBackends.md:115`).
- `@Level` syntax in `QuickReference.md:238-240` (`"2..5"`, bare number = exact) matches neither
  `Interval.java` (range is `(a,b)`/`(a;b)`, bare number means `>=`) nor the tutorial.
- `Troubleshooting.md:473` invents a console command `level 0`; the client menu has none. The
  `level=` script/agent argument (the only way to set the starting level) is documented nowhere.
- `BTraceTutorial.md:1366` says level changes retransform classes; in 3.0 it is a MethodHandle
  guard and handlers above the level still pay an indy call. (The guard itself was fail-open until
  `e579b70b` today; `createNoopMH` failures still fall back to the unguarded handler.)
- The "invokedynamic no-op after client exit" note has no doc hop; the nearest page
  (`ExtensionInvokeDynamicBridge.md:674-686`) lists call-site invalidation as future work.
- 3.0 client to 2.x agent pays the 5 s V2 negotiation timeout per connect; undocumented, and
  `btrace.protocol.negotiation.timeout` is missing from the QuickReference property table.
- `docs/README.md:21,64,86,109` still describe the MCP server as in-repo for Claude Desktop/Cursor;
  `MCPServer.md` and tutorial 05 correctly point at `btraceio/agent-plugins`.

CLI, agent options, prepared mode
- `Troubleshooting.md:117-145` tells users bare `println` fails and to add
  `import static io.btrace.core.BTraceUtils.*`, which actually suppresses the flat-DSL auto-import.
- `QuickReference.md:450` documents `-host`, absent from the client usage text; with `-host` the
  client skips discovery and cannot authenticate to a 3.0 prepared endpoint, contradicting the
  "remote prepared mode unsupported" statement with no caveat.
- Agent usage text (`messages.properties:109-137`) lacks `bindAddress`, `authTokenFile`,
  `telemetry`, and says `script` is comma-separated (it is colon-separated).
- Undocumented agent options: `cmdQueueLimit`, `trackRetransforms`, `scriptOutputDir`,
  `fileRollMilliseconds`, `fileRollMaxRolls`; `statsd=` only in usage text; `config=` only in an
  architecture page. QuickReference "Agent Parameters" also omits `allowExtensions`,
  `denyExtensions`, `allowPrivileged`.
- A plain `java -javaagent:btrace.jar MyApp` (no `port=`) is an authenticated prepared endpoint on
  port 2020; no doc says so. The `noServer` default rule (server unless `noServer=true`, or a
  `script=` is present and `noServer` unset) is never stated in one sentence.
- Prepared mode with an already-bound fixed port still aborts agent init (plain `BindException`
  escapes the new invalid-option catch); undocumented. Invalid-option behaviour is described in
  GettingStarted and QuickReference but `BTraceTutorial.md:122` still says "fail closed" and
  Troubleshooting has no entry for the new message.
- Telemetry opt-in appears only in GettingStarted and QuickReference; README and FAQ never mention
  telemetry or privacy.
- Tutorial 01 says re-run with `-Dbtrace.oneliner.dump=true` on the `btrace` command line; tutorial
  02 (correctly) says that does not work and uses `JAVA_TOOL_OPTIONS`.

Extensions
- `BTraceTutorial.md:870-889` StatsD example uses `StatsdExtension` / `timing(...)`; the shipped
  service is `io.btrace.statsd.Statsd` with only `increment(...)`.
- README/PermissionPolicy promise blocked extensions degrade to shims; non-optional `@Injected`
  never falls back and optional defaults to `THROW`.
- `btracex policy edit` is advertised (`tutorials/06:223`, `QuickReference.md:514`, installer
  hint) but prints "not yet implemented" and exits 2.
- `BTraceExtensionDevelopmentGuide.md:109` refers to `btrace ext inspect`; the tool is
  `btracex inspect`.
- `BTraceTutorial.md:1516,1646,1869,1878-1881` say to copy `btrace-<id>.jar` into `extensions/`;
  those jars do not exist, bundled extensions are already exploded there, and the supported path
  is `btracex install <zip>`.
- `tutorials/03-upgrade-from-2x.md:199` calls `libs=` a deprecation; it is removed.

## Nits
- Notes: "393 commits" is stale (437 today); "masked classdata" and "prepared mode" are used
  before definition and the Learn-more list lacks the masked-JAR and JDK-compatibility pages;
  Install section omits deb/rpm and docker pull; the injected imports are two
  (`io.btrace.BTrace.*` and `io.btrace.core.annotations.*`), not one.
- `NOTICE` says "Copyright 2008, 2024". `docker/README.md:333` and the three Dockerfile `ARG`
  defaults read `3.0.0-SNAPSHOT`.
- No doc enumerates the seven bundled extensions; `btrace-utils` is undocumented; "Extension
  Catalog" in `docs/README.md` links to a guide with no catalog.
- `GettingStarted.md:103` suggests `btrace -h`, which is not a flag. Doctor status wording differs
  between docs (`preparation required`), JSON (`preparation_required`) and human output.
- `ExtensionInterfaceRules.md:11` shows `@Injected(mode=...)` without `optional = true`;
  example manifests name the metrics extension "BTrace Metrics" (shipped: "BTrace HDR Histogram").
- `--version` includes the build commit but no doc says so, nor that it reads `dev` outside git.
