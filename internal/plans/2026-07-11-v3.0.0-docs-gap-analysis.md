## 2. Java-version claims are a three-way contradiction (blocker)
- `docs/GettingStarted.md:17` — "Java 8 or higher (BTrace supports Java 8-20)" (repeated at :833)
- `docs/FAQ.md:33,443` — "Java 8 through Java 20"
- `docs/Troubleshooting.md:579` — "BTrace supports Java 8+" (while :561 documents JDK 25 behavior)
- `docs/README.md:154` — "Java Compatibility: Java 8-25"
- `docs/MCPServer.md:13` — MCP needs JDK 11+ (fine, but should be restated relative to the new floor)
- `docs/releasing.md:43` — integration tests on 8/11/17/21

3.0 target statement (single canonical formulation to use everywhere):
> BTrace 3.0 runs on Java 8–25+. Running on Java older than 17 is **deprecated**: it works fully in 3.x but prints a deprecation warning, and support will be **removed in the next major release (4.0)**.

## 4. Missing documents (to create)
1. **`docs/Migration-2.x-to-3.0.md`** — the single most important missing doc for this release. It can (and should) be short, because most migration is automatic; its job is to say so authoritatively:
   - Compiled/persisted probes: **no action** — `ProbePackageMigrator` remaps `org/openjdk/btrace/` → `io/btrace/` transparently at load time.
   - Script sources: mechanical import rewrite (`org.openjdk.btrace` → `io.btrace`); with the new auto-imports most scripts can simply *drop* the imports. Ship/point to an automated rewrite (sed one-liner or helper script — see release plan Phase 3 item 3a).
   - The rest is a checklist: Maven coordinates `io.btrace:*`, masked-JAR packaging change, `btrace-instr` artifact removal, libs→extensions migration pointer, wire-protocol compatibility statement, Apache-2.0 note, and the Java < 17 deprecation policy with the 4.0 removal notice.
2. **Java support policy section** (in README + `docs/README.md` + FAQ entry) — the canonical statement from §2, plus the exact warning text users will see and how to interpret it. Consider documenting an opt-out sysprop for the warning (decision in release plan).
3. **ClassFile API backend doc** — user-level paragraph (Troubleshooting/FAQ: "what happens on JDK 26+ classes; JDK 24+ agent uses ClassFile API; ENTRY/RETURN only for now") + `docs/architecture/InstrumentationBackends.md` reference doc (SPI, BackendSelector, ASM ceiling 69, non-MRJAR packaging rationale).
4. **Wire protocol V2 user note** — QuickReference/FAQ entry with the correct sysprops and the negotiation/fallback story.
5. **`docs/ExtensionRegistry.md`** — either write it (registry JSON catalog format `btracex install` consumes) or remove the three dangling references.
6. **`btrace-maven-plugin/README.md`** — even a stub pointing to the Gradle-plugin README section.
7. Per-extension READMEs for shipped modules (`btrace-metrics`, `btrace-statsd`, `btrace-utils`, `btrace-contracts`, `btrace-llm-trace`, `btrace-rag-quality`, `btrace-gpu-bridge`) — a short template each: what it does, permissions required, `@Injected` snippet, link to tutorial lesson.
8. **`docs/TUI.md`** + the two referenced images, or drop the README references (§3.13).
