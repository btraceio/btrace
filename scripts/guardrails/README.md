# Guardrails

Deterministic checks for rules that advisory text (AGENTS.md, CLAUDE.md, skills) cannot enforce.

## Where each gate runs and what blocks a merge

- The Python checks G1, G2, G4, G6, G9 (`check_launchers.py`, `check_kind_dispatch.py`), G10, G11
  (`check_runtime_safety.py`), G12 (`check_message_keys.py`) and G13, and their own tests, run in
  the `guardrails` job of `.github/workflows/continuous.yml`. That job feeds the aggregate
  `tests-passed` check, together with `build`, the integration test lanes, the qe harness and the
  Gradle plugin tests.
- G5 (`check_pr_metadata.py`: the title, the Testing section, golden data, and the `Sibling:` line
  for a one-sided backend change) runs in `.github/workflows/pr-metadata.yml` as the `pr-metadata`
  check.
- The JUnit and compiler gates run in the `build` job (`./gradlew build`): `BootstrapClosureTest`
  (G7), the Java 8 API setting in `common.gradle` and the module build scripts (G8),
  `CommandTableParityTest` (G9), `BTraceTransformerFailureReportTest` (G11), `ArgsRegistryTest`
  and `HandlerAnnotationClassificationTest` (G12).

A failing check blocks merging only if the repository's branch rules require it. Read on
2026-11-14 with `gh api repos/btraceio/btrace/rulesets/26315659`, the "Merging" ruleset for
`develop` and `master` requires the status checks `build`, `tests-passed` and `pr-metadata`, so
every gate above blocks a merge. The same ruleset has `require_code_owner_review: false` and
requires no approving review, so `.github/CODEOWNERS` requests the maintainer's review of the
guardrail files, baselines and exception lists but does not block a merge without it.

| `check_swallow.py` (G10) | No new `catch` of `Throwable`, `Exception` or `RuntimeException` (alone or in a multi-catch) whose block is empty, only `log.debug`/`log.trace`, or a bare `return`/`return null`/`return false`/`continue`/`break` (a mix of those, e.g. `log.debug(..); return false;`, counts too), in `*/src/main/` Java. A catch block whose braces cannot be parsed fails rather than being skipped, and the diff is read in a pinned format so user git config cannot hide a file. | `check_pr_metadata.py` (G5) | The PR title is a Conventional Commit subject (it becomes the squash-merge subject). For a PR not opened by a bot, also: the description has a filled Testing / How verified section; a change to golden instrumentation data says it was regenerated with `-PupdateTestData`; a change to exactly one instrumentation backend (ASM files listed in `ASM_BACKEND`, or `btrace-agent/src/main/java24/`) has a `Sibling: <reason>` line on one line (presence, not adequacy). Runs in its own workflow, `.github/workflows/pr-metadata.yml`, so editing the description re-runs only this check | `python3 scripts/guardrails/check_pr_metadata.py event.json changed-files.txt` |
| `check_layering.py` (G6) | Module layering is fixed: every `project(':x')` in a `build.gradle` is an edge and the edges equal the allowlist in `layering_rules.json` (a non-literal `project(expr)` needs a listed reason); `btrace-boot`, `btrace-core`, `btrace-client`, extensions, `btrace-qe`, `integration-tests` and `io.btrace.instr` import no forbidden package (single-type, static and wildcard imports, every source set); no string literal in a lower layer names a higher-layer class; no Java package is split across modules; a module `build.gradle` that clears or changes `options.release` (the `--release 8` API gate of P3) must be listed under `release_opt_outs` with a reason, and a listed one that no longer does is stale. | `check_launchers.py` (G9) | Each `btrace-dist/.../bin/<name>` and its `.bat` twin pass the same JVM flags (`-X`, `-XX:`, `-D`, `--add-exports`/`--add-opens` with their argument) and start the same main class; CRLF and `^`/`\` continuations are normalised. Existing violations are in `bootstrap-closure-baseline.txt`; a new one and a listed one that is gone both fail. A missing jar, a jar with no root classes or an unreadable class fails, not passes. A JUnit test in `btrace-dist`, so `./gradlew build` already runs it | `./gradlew clean :btrace-dist:btraceJar :btrace-dist:test --tests '*BootstrapClosureTest'` |
| `ArgsRegistryTest` (G12) | Every `public static final String` of `io.btrace.core.Args` is documented in the `btrace.agent.usage` value of `messages.properties` (the name is a list head: a comma-separated name starting a line indented by exactly two spaces in the loaded value, followed by whitespace; the word inside a description does not count) and in `docs/QuickReference.md` (`name=` as a whole identifier; the bare word in prose or `scriptOutputFile=` for `output` does not count). A compiler setting, so it runs in every build, not in the `guardrails` job | `./gradlew compileJava` |

Each check has tests under `tests/` that build throw-away trees or repositories and assert the
check fails on bad input with the expected message, and passes on good input. Three tests in
`test_check_pr_metadata.py` read the real tree instead, on purpose: the one that fails when
`ASM_BACKEND` is stale (it runs `derive_asm_backend.py` on the repository), the one that checks
every `ASM_BACKEND` path and the `CLASSFILE_BACKEND` directory exist, and the one that checks
`pr-metadata.yml` lists both sides of a rename. Every baseline entry read through `_baseline.py`
must carry a `# reason`; an entry without one fails the check, naming the file and line.
`_baseline.py` and `_common.py` are helper modules shared by the checks, not checks.

```bash
python3 -m unittest discover -s scripts/guardrails/tests -p 'test_*.py'
```

When you add a check, add its tests in the same change, show them failing with the check
disabled, and list it in the table above. Background and the full gate list:
[the guardrails proposal](../../internal/plans/2026-11-04-agent-guardrails-proposal.md).
