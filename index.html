Extensions

Eight bundled extensions. You decide what each may do.

Extensions replace libs= profiles and the Aggregations API. Each declares the permissions it needs, and you grant them on the agent side. btrace -le explains why an extension is blocked.

Permissions → Write your own →
btrace-metrics Latency histograms and stats: p50, p95, p99.
btrace-contracts Latency budgets, call-rate limits, assertions and tagged path profiles.
btrace-otel Sends spans, counters and gauges to an OTLP/HTTP collector.
btrace-statsd Sends metrics to a StatsD endpoint.
btrace-utils Common helper functions for probes.
06 // Production

Attach safely to production JVMs.

Check the JVM before you load a probe. When the client detaches, the probe has no cost.

01

Prepare

-javaagent:btrace.jar=port=0

Start the JVM in prepared mode. It listens on localhost only, requires a token, and instruments nothing.

02

Check

btrace doctor <pid>

Reports whether the JVM is ready, with a scriptable exit code. Loads nothing.

03

Attach and detach

btrace <pid> HotPathProbe.java

The client finds the endpoint and token by itself. On exit, the original bytecode is restored.

// btrace doctor, two JVMs
$ btrace doctor 39936
Status: READY (exit 0)
BTrace endpoint: ready at 127.0.0.1:58103
Authentication: required; credential file readable

One btrace.jar.

Replaces the three-jar layout. Runs on Java 8 to 27. Support for Java below 17 is deprecated and ends in 4.0.
